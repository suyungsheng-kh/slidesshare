初階 · 先懂再操作

四個名詞決定問題應該在哪裡處理

前端

教師與學生看到的 HTML 網頁。它只負責填資料、上傳檔案與顯示結果，不直接呼叫 Gemini。

後端

在 Colab 執行的 Python 程式。它解析 .sb3、排隊、呼叫 AI，並決定能否正式評分。

Secret

不能公開的密碼或憑證，例如 ngrok authtoken 與 ADMIN_TOKEN。只放在 Colab Secrets。

API 網址

ngrok 提供的公開 HTTPS 地址。它可以放在 app-config.js，因為網址本身不是密碼。

記法：網頁把作品送到 API 網址，後端讀取 Secret，再替學生完成評分。
來源：系統架構與檔案先建立心智模型

初階 · 啟動後端

第二格讀取 Secrets，第三格啟動服務

# 第 2 格：讀取三個必要 Secret
import os
from google.colab import userdata

required = ['NGROK_AUTHTOKEN',
            'NGROK_STATIC_DOMAIN',
            'ADMIN_TOKEN']
for name in required:
    os.environ[name] = userdata.get(name)

missing = [n for n in required if not os.environ.get(n)]
if missing:
    raise RuntimeError('缺少：' + ', '.join(missing))
# 第 3 格：啟動背景服務
import importlib
import colab_server
importlib.reload(colab_server)

public_url = colab_server.serve_background()
print('公開 API：', public_url)
成功訊號：輸出出現「API 已上線（背景執行）」以及一個 https://...ngrok-free.app 網址。把完整網址複製到安全筆記。

進階 · 評分策略

改門檻很容易，改評分語意要重新建立證據

只改達成門檻

教師頁調整 75／90 分即可。星等由 grading_assessment.py 固定換算，不必改提示詞。

改規則與配分

把規則寫成可在積木流程中直接觀察的條件。儲存後，該關四份樣本重新校正。

改提示詞或輸出

調整 generate_grading_prompt()，提升 GRADING_PROMPT_VERSION，所有關卡重新校正。

避免只用一份「正確答案」測試：邏輯陷阱樣本能檢查 AI 是否只看外觀或角色數量；少一條規則樣本能檢查配分是否真的被遵守。
來源：校正指紋與四種案例改變即重新校正
17 / 19

進階 · 容量與資料

從個人試用走向班級使用，需要三個決定

同時多少人送出

MAX_CONCURRENT_GRADES 控制同時評分，MAX_QUEUED_GRADES 控制等候上限。先看實測平均時間與 API 額度，再提高。

資料要保存多久

需要跨 Colab 重啟時啟用 Firestore。不同班級至少分開 collection／document，避免最後儲存者覆蓋設定。

誰能管理

單一 ADMIN_TOKEN 適合小型自用。多位教師、角色權限或正式校務資料，應改為真正的身分登入與稽核紀錄。

容量不是只改一個數字：提高併發會同時增加 Colab 負載、模型請求速率與費用風險。佇列統計是調整依據，不是完成時間保證。
來源：FIFO 佇列與 README 參數先量測再放大
