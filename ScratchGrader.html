新版解析 · 教師需要理解的界線

程式結構與實際執行結果的差別

存檔值是快照

變數與清單的存檔內容不代表程式真的產生該結果。評分要檢查處理資料的積木流程。

程式語意要完整

新版補充自訂積木、分身建立時狀態、區域變數獨立性，以及同事件多段程式的啟動方式。

證據不足需確認

未知擴充或超長截斷內容會標示限制，模型不能憑猜測扣分。教師需回 Scratch 檢查作品。

人工先確認樣本

教師親自在 Scratch 執行四種作品，先寫下哪些要求成立與期望分數，再進行模型校正。

使用界線：系統讀取程式並分析，沒有實際執行 Scratch 作品。算分格式正確仍可能判斷錯功能，正式成績需由教師覆核。

一份 .sb3 如何變成學生看得懂的回饋

初階 · 先懂再操作

四個名詞決定問題應該在哪裡處理

前端

教師與學生看到的 HTML 網頁。它只負責填資料、上傳檔案與顯示結果，不直接呼叫 Gemini。

後端

在 Colab 執行的 Python 程式。它解析 .sb3、排隊、呼叫 AI，並決定能否正式評分。

Secret

不能公開的密碼或憑證，例如 ngrok authtoken 與 ADMIN_TOKEN。只放在 Colab Secrets。

API 網址

ngrok 提供的公開 HTTPS 地址。它可以放在 app-config.js，因為網址本身不是密碼。

記法：網頁把作品送到 API 網址，後端讀取 Secret，再替學生完成評分。
來源：系統架構與檔案先建立心智模型

from google.colab import userdata

for name in required:
    os.environ[name] = userdata.get(name)

# 新增選用 Secret 後也要讀入環境
optional = ['CORS_ALLOWED_ORIGINS']
for name in optional:

初階 · 規則定稿

一般試評、儲存與正式校正的用途

⑥ 一般試評

選作品與供應商，按「一般試評」。可測③尚未儲存的規則，檢查扣分證據、講評與等效解法。

⑤ 儲存設定

解答得到 100 分的原因：一般試評保留參考解答政策。勾選「與參考解答一致即滿分」時，可能走捷徑，仍需用正式盲評檢查模型判斷。

確認扣分指向真正缺少的功能、沒有新增題外要求，且講評與扣分一致。API 或回覆格式失敗應修復重試，不算學生 0 分。

初階 · 校正不符預期

校正失敗的原因與修訂流程

完整作品被扣題外要求

在③明列教學範圍與等效解法，刪除模糊要求，再儲存與重測。

缺功能卻拿滿分

補上具體查核條件與部分完成界線。例如要求索引逐次變動，不能只寫「有迴圈」。

跨模型分差過大

比較兩邊扣了哪些規則，釐清措辭與配分。提高容許分差不能解決判斷分歧。

樣本或 API 有問題

回 Scratch 修正樣本，或修復金鑰、模型與回覆格式後重試。服務失敗不算校正通過。

政策改動的流程：修改③標準，按⑤儲存，重新完成⑥全部校正。規則、範本、解答、模型、備援、門檻、容許分差或分析版本改動，都會使舊校正失效。

只替換某情境樣本而未改政策時，其他情境可保留；所有啟用模型重測該份新作品。不要看完 AI 分數才放寬期望範圍，仍須覆核評語與證據。

進階 · 評分策略

改門檻很容易，改評分語意要重新建立證據

只改達成門檻

教師頁調整 75／90 分，星等由 grading_assessment.py 換算。儲存後舊校正失效，仍需重新校正。

改規則與配分

把規則寫成可在積木流程中直接觀察的條件。儲存後，該關四份樣本重新校正。

改提示詞或輸出

提升 GRADING_PROMPT_VERSION，影響正式評分時也提升 GRADING_POLICY_VERSION。重啟並重新校正所有受影響關卡。

後端格式契約：分數為 100 − 扣分 + 加分，限制 0～110 並四捨五入。完全相同的重複扣分合併，同規則衝突、缺少明細或非法數值視為失敗，不保存正式成績。

Claude 正式備援預設關閉，需在部署端同時設定啟用值與 Anthropic key。啟用後只在主模型 503 或連續兩次 500 時切換，429 額度限制不會自動轉為付費 Claude。
